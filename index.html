What is IAM?

IAM = Identity and Access Management. It's the AWS service that answers two questions on every single request: Who are you? (authentication) and What are you allowed to do? (authorization).

Analogy: an office building. IAM is the reception desk + key-card system. Users are people with ID cards, groups are departments (Finance, Engineering), policies are the rules printed on the card: "Floor 3 only, 9 to 6".

IAM is free and global (not tied to a region).

Setup

No account? Create one at aws.amazon.com/free. Set a billing alert: Billing → Budgets → Create budget → "Zero spend budget".

Root vs IAM user: which to use?

Root = the email you signed up with. It can do everything, including close the account. Use it only for rare account-level tasks. Everything else: an IAM/Identity Center admin user with MFA. Today it's OK to use root if you don't have one yet, and we'll improve that in the hardening module.

What is a Region?

A physical location where AWS runs data centres (Mumbai, Singapore, N. Virginia…). Resources you create (like EC2) live in one region. Pick one near your users for speed; pick the one where your free tier applies. IAM stuff (users, policies) is global, so it works across regions.

It lets you stay logged in as admin in one window while testing the intern in the other. (Different browser profile works too.)

Jugaad mindset

Jugaad = a clever fix with what you've got. In SRE that means the smallest permission that works. Never hand out AdministratorAccess "just to make it work".

World 1-1 · Build

Launch two EC2 instances

Jugaad Corp has a lab server where experiments happen and a prod server that customers use. Everything we do next exists to protect these two.
By the end of this module you'll have:
  • jugaad-lab-server tagged Env=lab
  • jugaad-prod-server tagged Env=prod
  • Proof, as admin, that you can control both (our baseline)

What is EC2?

EC2 = Elastic Compute Cloud (two C's, hence EC2). It rents you virtual computers ("instances") by the second. You choose the OS, CPU, memory, and AWS runs it in a data centre.

Analogy: renting a laptop from a giant warehouse. Switch it on, use it, switch it off, pay only while it's on.

Launch instance #1 (lab)

Click Add additional tags → Key Env, Value lab, Resource type Instances.

Why are we adding a tag?

A tag is a label (key + value) on an AWS resource. Our IAM policy will say "allow stop/start only if Env is lab". Without the tag, the policy has nothing to match. Tag keys and values are case-sensitive: env ≠ Env.

What is an AMI?

Amazon Machine Image: the template of the operating system (+ pre-installed software) your instance starts from.

Options & what to choose

OptionWhen to use
Amazon Linux 2023Default for AWS work: free-tier eligible, tuned for AWS, patched by Amazon. Our pick.
UbuntuIf your team/tutorials use Ubuntu and apt.
Windows Server.NET / Windows apps. Costs more (licence).
macOSiOS/macOS build farms. Expensive, 24h minimum.

What is an instance type?

The hardware size: vCPUs and RAM. Name pattern: family + generation . size, e.g. t3.micro = family t (burstable, cheap), generation 3, size micro (2 vCPU, 1 GiB RAM).

Options & what to choose

FamilyGood for
t (t3, t2)Light/bursty workloads, learning. Our pick.
m (general purpose)Balanced production apps
c (compute)CPU-heavy: builds, encoding
r (memory)Databases, caches

Newer AWS accounts may use a credits-based free plan instead of "free tier eligible" labels. Either way, micro for a short lab costs cents.

What is a key pair?

A public/private key used to SSH into a Linux instance. AWS keeps the public half, you download the private .pem file once.

Options & what to choose

OptionWhen
Proceed without a key pairToday: we never log in to the machine, we only control it from the console.
Create new key pair (RSA / ED25519)When you do need SSH. ED25519 is newer and smaller; RSA is the most compatible. Keep the .pem file private.
Use existingReuse a key you already created

In real jobs, prefer SSM Session Manager (no open port, no key files).

What is a security group?

A virtual firewall around the instance. Rules say which traffic may reach it (port 22 = SSH, 80 = HTTP, 443 = HTTPS). Everything not allowed is blocked.

Options & what to choose

SettingPick
Create security group, no inbound rulesSafest for today. Nothing can reach the machine.
SSH from "Anywhere" (0.0.0.0/0)Avoid. The whole internet can try to log in.
SSH from "My IP"OK if you really need SSH.

gp3 is the current general-purpose SSD volume. Default is fine; bigger disks cost more.

Launch instance #2 (prod)

Same AMI, type, no key pair. Only the name and tag value change.

🎯 Prove it: you, the admin, can control both

That's exactly how IAM will "see" your tag later. Clear the filter, then try tag:Env=prod.

It worked because you're an admin. Remember this feeling: in the next modules an intern will try the same click and AWS will say no.

Two tagged instances, and you've seen that an admin can stop and start both. This is our baseline.
Feeling stuck? Common problems
  • Can't find "Launch instances": make sure you're in EC2 → Instances, not "Dashboard".
  • Instance type not available: pick another micro/small the console lists.
  • Vcpu limit error: new accounts have low limits. Try another region or ask AWS Support to raise it.
World 1-2 · Users

Create a user and meet "implicit deny"

Intern Ishaan starts Monday. You create his account first, and before giving him anything, you check what a brand-new user can do.
By the end of this module you'll have:
  • A friendly sign-in URL (account alias)
  • User jugaad-intern

What is an account alias?

A nickname for your AWS account that becomes part of your users' sign-in URL: https://<alias>.signin.aws.amazon.com/console instead of the 12-digit account number. Easier to remember, share and trust.

Rules: 3–63 characters, lowercase letters, digits, hyphens; must be unique across all of AWS.

Try jugaad-corp-<your-name>-<digits>. If it's taken, tweak it. Copy the Sign-in URL for IAM users into a notepad.

What is an IAM user?

A person or app inside your AWS account, with its own name and long-term credentials (a password, and optionally access keys). By itself a user can do nothing; permissions are given separately.

Users, groups, roles: what's the difference?

IdentityIs…Use for
UserA person/app with long-term credentialsIndividual humans (in small setups)
GroupA collection of users sharing permissionsTeams: "operators", "viewers"
RoleAn identity you assume temporarily, no passwordServers, apps, cross-account, short elevated access (Module 6)

🎯 Prove it: log in as the intern

Account = your alias (pre-filled), IAM user name jugaad-intern, your password. Set the region to ap-south-1.

You'll see red "You are not authorized to perform…" messages, and no instances. Click Instance state on anything you can find: nothing works.

Reading the error message

It tells you who (the user ARN), what (e.g. ec2:DescribeInstances) and why ("no identity-based policy allows" = implicit deny). This message is your best debugging friend.

The intern can log in but can do nothing. AWS is deny by default. Keep this incognito window open: you'll refresh it after each module.

World 1-3 · Policies

Write a policy, attach it, watch ALLOW and DENY appear

Time to turn your manager's sentence into JSON: "restart lab, never touch prod". Then test it on Ishaan, live.
By the end of this module you'll have:
  • Policy JugaadLabOperator
  • Group jugaad-operators containing the intern
  • Proof the intern can stop lab but not prod

What do IAM Policies do?

An IAM policy is a written rule that says who can do what with your AWS resources. Every time someone tries to start a server, open a bucket or read a secret, AWS checks the policies that apply to them and answers ALLOW or DENY.

On their own, policies do nothing. They only take effect once they are attached to a user, a user group or a role. Attach one to a group and everyone in that group gets the same rules.

Without any policy, the answer is always DENY. That's exactly what you saw in the last module.

Types of policy: what to choose

TypeWhat it isWhen
AWS managedWritten & updated by AWS (e.g. AmazonEC2ReadOnlyAccess)Quick start; often broader than you need
Customer managedYou write it, reusable on many identities, versionedOur pick: precise and reusable
InlineEmbedded in one single user/group/roleRare one-offs; hard to audit

Create the policy

Visual vs JSON editor

ModePick when
VisualLearning, small policies, you want dropdowns
JSONOur pick: faster, copy-pasteable, what you'll see in real repos
JugaadLabOperator.json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "SeeEverything",
      "Effect": "Allow",
      "Action": "ec2:Describe*",
      "Resource": "*"
    },
    {
      "Sid": "StartStopOnlyLabTagged",
      "Effect": "Allow",
      "Action": [
        "ec2:StartInstances",
        "ec2:StopInstances"
      ],
      "Resource": "arn:aws:ec2:*:*:instance/*",
      "Condition": {
        "StringEquals": { "aws:ResourceTag/Env": "lab" }
      }
    }
  ]
}
Read it like a sentence

Rule 1: allow listing/viewing EC2 things everywhere. (Describe actions can't be limited per-resource, so * is required.)
Rule 2: allow starting and stopping instances, but only if the instance's Env tag equals lab.

Nothing grants terminate, create or delete, so those stay denied by default.

What are we doing right now?

We're writing the rule in JSON, the format AWS stores every policy in. The pasted policy has two statements: one lets people see EC2 resources, the other lets them start and stop only the instances tagged Env=lab. Nothing else is granted, so prod stays untouched.

Add a description like "Start/stop Env=lab EC2 only". Future you will thank you.

Extra for Experts: how are JSON policies structured?

Let's unpack the policy you just pasted. Every policy is built from the same few pieces:

Version
The policy language version. It's always 2012-10-17, the current one.

Statement
The main body: a list of rules. Our policy has two. Each rule can carry an optional Sid, a human-readable label such as SeeEverything.

Effect
Allow or Deny. If two rules clash, an explicit Deny always wins.

Action
The things a person may do, written as service:Operation, for example ec2:StopInstances. A star is a wildcard, so ec2:Describe* covers every Describe action.

Resource
What the rule applies to, written as an ARN (Amazon Resource Name). A single * means everything. Ours points at EC2 instances only.

Condition (optional)
An extra "only if" test. Ours checks the instance tag, so the rule applies only when Env equals lab. Conditions can also check IP address, time of day or whether MFA was used.

Attach it through a group

What is a user group?

A collection of users that share the same permissions. You attach policies to the group, then add people. When someone changes team you move them, you don't rewrite policies.

🎯 Prove it: the intern's new powers

The red errors disappear and you now see both servers. ALLOW View.

Instance state → Stop instance works. ALLOW Stop lab. (Start it again.)

Red banner: "You are not authorized to perform: ec2:StopInstances". DENY Stop prod. Same user, same action, different tag.

Both DENY. Nobody granted those actions, so the default applies.

Same user, same policy, different tag → DENY. That's tag-based access control (ABAC) in action.

How AWS decides: ALLOW vs DENY

Request arrives
→
Any matching explicit Deny?
→
Yes → DENY
No →
Any matching Allow?
→
Yes → ALLOW
No → implicit DENY

Power order: explicit Deny > Allow > implicit Deny (the default).

The intern controls only the lab server. "Never touch prod" is now enforced by AWS, not by trust.
Feeling stuck? Lab stop is being denied
  • Tag spelled differently? Must be exactly Env=lab.
  • Is the intern really in jugaad-operators? IAM → User groups → Users tab.
  • Is JugaadLabOperator on the group? Check the Permissions tab.
  • Red marker in the JSON editor = a missing comma/bracket. Re-copy with the Copy button.
  • Wait ~30 seconds after changes; IAM is eventually consistent.

World 2-1 · MFA

Lock the intern's login with MFA (use your phone)

Ishaan reuses passwords everywhere. If his password leaks, someone could stop your lab server. Let's make a stolen password useless by tying his login to a phone.
By the end of this module you'll have:
  • An MFA device on jugaad-intern using an authenticator app on your phone
  • Logged in with password and the 6-digit code
  • Seen a wrong code get rejected

What is MFA?

Multi-Factor Authentication: you prove who you are with two different things: something you know (password) and something you have (your phone generating a code that changes every 30 seconds). A leaked password alone is no longer enough.

MFA options & what to choose

TypeNotes
Authenticator app (virtual MFA)Free, takes a minute. Google Authenticator, Microsoft Authenticator, Authy. Our pick.
Passkey / security key (FIDO2)Strongest, phishing-resistant. Needs a compatible device or hardware key.
Hardware TOTP tokenA physical keyfob. Used by some regulated companies.

Set it up

Device name intern-phone → choose Authenticator app → Next.

A new entry "AWS … jugaad-intern" appears in your app with a 6-digit code.

Can't scan?

Click Show secret key and type it into the app manually.

AWS asks for two codes to confirm the clock on your phone and AWS agree.

🎯 Prove it: log in with the code

After the password a new screen asks for an MFA code. A thief with only the password stops here.

AWS rejects it. Now open your phone, read the real 6-digit code, and enter it before it refreshes.

Logging in as the intern now needs password + phone. Permissions are unchanged. MFA only protects who gets in.
Jugaad tip

Do this for your own admin user too, and for the root user. In real companies you can even write policies that deny everything unless MFA was used, using the condition aws:MultiFactorAuthPresent.

World 2-2 · Roles

Roles: borrow powers for an hour

Prod is on fire at 2 a.m. and Ishaan is the only one online. You don't want to give him permanent prod access, so you create a role he can switch into for a short time.
By the end of this module you'll have:
  • Policy + role JugaadProdOperator
  • A permission letting the operators group assume that role
  • Proof: the intern stops prod while wearing the role, and is denied again after switching back

What is an IAM role?

An identity with permissions but no password and no permanent keys. Someone (or something) assumes it and receives temporary credentials that expire, 1 hour by default. A role has two parts: a trust policy (who may assume it) and permission policies (what it can do).

Analogy: a hotel master key card kept at reception. You borrow it for a while, do the job, hand it back.

Who can assume a role: what to choose

Trusted entityUse for
AWS serviceEC2, Lambda etc. needing to call other AWS services
AWS account (this account)People in your account borrowing extra access. Our pick.
AWS account (another)Cross-account access, partners
Web identity / SAMLLogin with Google/Cognito or company SSO

Create the role's permissions

JugaadProdOperatorPolicy.json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "ec2:Describe*",
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": ["ec2:StartInstances", "ec2:StopInstances"],
      "Resource": "arn:aws:ec2:*:*:instance/*",
      "Condition": {
        "StringEquals": { "aws:ResourceTag/Env": "prod" }
      }
    }
  ]
}

Same shape as before, only the tag value changed to prod.

Let the operators group assume it

JugaadAssumeProdRole.json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": "sts:AssumeRole",
    "Resource": "arn:aws:iam::<ACCOUNT_ID>:role/JugaadProdOperator"
  }]
}

Replace <ACCOUNT_ID> with your number. sts:AssumeRole is the permission to "put on" a role.

🎯 Prove it: wear the role

The top bar now shows the role name instead of the intern's name.

The intern just did what he was denied minutes ago, with temporary credentials and no change to his own permissions.

DENY. While you wear a role you give up your own permissions and have only the role's. Then use Switch back from the menu, and prod is denied again.

Roles give powerful access that is temporary, auditable (CloudTrail logs who assumed it) and revocable.
Feeling stuck? Switch role fails
  • "Not authorized to switch": check the policy is attached to the group and the Account ID and role name are exact.
  • Role name is case-sensitive: JugaadProdOperator.
  • Wait ~30 seconds after attaching the policy.

What is the IAM Policy Simulator?

A tool that evaluates policies against actions you choose, and tells you allowed / denied and which statement decided. No real API calls are made, so nothing gets stopped or deleted.

Select service Amazon EC2, actions DescribeInstances, StopInstances, TerminateInstances → Run simulation. Compare with what you saw live.

Why might StopInstances show "denied" here?

The simulator doesn't know your instance's tag unless you tell it. Our policy only allows when aws:ResourceTag/Env = lab. Add that as a context key in the simulator settings. Missing information = condition not met = deny.

Create this policy, attach it to jugaad-operators, retry Stop on the lab server as intern, then detach it.

JugaadFreezeStops.json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "FreezeStops",
    "Effect": "Deny",
    "Action": "ec2:StopInstances",
    "Resource": "*"
  }]
}

Click the CloudShell icon in the top bar (no install). Replace <ACCOUNT_ID>.

CloudShell
aws sts get-caller-identity

aws iam simulate-principal-policy \
  --policy-source-arn arn:aws:iam::<ACCOUNT_ID>:user/jugaad-intern \
  --action-names ec2:StopInstances ec2:TerminateInstances \
  --context-entries "ContextKeyName=aws:ResourceTag/Env,ContextKeyValues=lab,ContextKeyType=string" \
  --query 'EvaluationResults[].[EvalActionName,EvalDecision]' --output table
